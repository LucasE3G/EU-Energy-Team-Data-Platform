Adding the heatwave map to WordPress

The map is a single self-contained block of HTML. In the normal case this is a copy-and-paste job that takes about two minutes and needs no plugin, no developer and no upload. There is one WordPress permission that decides whether that works, and a fallback for when it does not.

1.  What you have

FileSizeUse it for
heatwave-map-embed.html111 KB Route A. The widget on its own — styles, markup and script, nothing else. Select all, paste into one Custom HTML block.
heatwave-map.html113 KB Route B, and for previewing. A complete web page: double-click it and it opens in a browser. This is the file you upload.
heatwave-map-iframe.html2 KB Route B. The frame code, both versions, ready to paste. Not a page — a snippet.

Both carry the data inside them. There is no database call, no API key, no external file and no network request of any kind at page load. Nothing needs to be kept running for the map to work, and it will keep working if this project is switched off.

2.  The one thing that decides which route

WordPress deletes <script> and <style> tags from page content when it is saved, unless the person saving has a permission called unfiltered_html. The map needs both tags, so this is the whole question.

Your situationDo you have it?
Administrator or Editor, ordinary single-site WordPressYes — use Route A
Author or Contributor, any setupNo — Route B, or ask an Administrator to paste it
Any role on a WordPress multisite networkNo, unless you are a Super Admin
Managed hosts and some security pluginsSometimes switched off deliberately — test it

The two-minute test, which is faster than finding out

Make a new draft page. Add a Custom HTML block, paste in <script>console.log(1)</script>, click Save draft, then reload the editor page in your browser. If the tag is still there, you have the permission and Route A will work. If it has vanished, go to Route B.

Reloading matters. Until you reload, the editor shows you what you typed rather than what WordPress stored.

Route A Paste it into the page

The normal route. Two minutes, no upload, no plugin.

  1. Open heatwave-map-embed.html in a plain-text editor — Notepad, TextEdit, VS Code. Not Word or Google Docs: they rewrite quotes and dashes and will silently corrupt the file.
  2. Select all (Ctrl+A) and copy (Ctrl+C).
  3. In WordPress, open the page and put the cursor where the map should go.
  4. Click +, search for Custom HTML, and add that block. It must be Custom HTML — a Paragraph block will show the code as text.
  5. Paste. The block will look like a wall of code; that is correct.
  6. Click Preview → Preview in new tab. The editor itself does not run the script, so the block will still look like code until you preview.
  7. Publish or Update, then load the live page and click a country.

If the block shows code on the published page too

The paste went into a Paragraph or Code block rather than a Custom HTML block. Delete it and add the block again via + → Custom HTML.

Route B Serve it in a frame

Use this only if the test in section 2 failed. The map is identical; it just lives in its own file and the page shows a window onto it.

  1. Upload heatwave-map.html to the server — for example to /wp-content/uploads/heatwave-map.html. The Media Library will refuse it: WordPress blocks .html uploads by default. Use SFTP or your host's File Manager, or ask whoever administers the site.
  2. Check it works on its own by visiting https://your-site/wp-content/uploads/heatwave-map.html directly. If it does not load here, nothing later will help.
  3. Open heatwave-map-iframe.html. It holds two options; change the address in the one you use to match step 1, then paste that one into a Custom HTML block.

Option 1 — the frame sizes itself (use this if you can)

The map measures itself and tells the page how tall to make the frame, so nothing is ever cut off and it adapts on a phone. It needs a <script> tag to survive, so it is only available if the section 2 test passed and you are choosing a frame for another reason.

<iframe id="hwmap-frame" src="/wp-content/uploads/heatwave-map.html"
        title="European electricity demand during the 2026 heatwaves"
        loading="lazy" style="width:100%; border:0; display:block; height:820px"></iframe>
<script>
addEventListener('message', function (e) {
  if (e.data && e.data.hwmap === 'height') {
    var f = document.getElementById('hwmap-frame');
    if (f) f.style.height = e.data.height + 'px';
  }
});
</script>

Option 2 — fixed height (no script anywhere)

<iframe src="/wp-content/uploads/heatwave-map.html"
        title="European electricity demand during the 2026 heatwaves"
        loading="lazy"
        style="width:100%; border:0; display:block; height:830px"></iframe>

Pick the height from the width of the column the map sits in. Measured in a real frame, not estimated:

Column widthHeight neededNotes
1110 px (full-width E3G container)1060 px
920 px930 px
730 px (E3G narrow container)800 pxUse 830 px for margin
600 px715 px
Under about 590 px (phones)up to 1120 px The country card moves below the map, so the page grows when one is open

A fixed height cannot be right at every screen size — a phone needs roughly the height a desktop does, for a much narrower map. Where the frame is too short it scrolls internally: nothing is lost, it just reads worse. Option 1 avoids this entirely, which is why it is worth using where it is available.

3.  Checking it worked

On the published page, not the editor:

  • The map draws, with countries shaded cream through dark rust.
  • Hovering a country shows a small tooltip with its name.
  • Clicking a country opens a card with an arrow pointing at it. Clicking the ×, pressing Escape, or clicking off the map closes it.
  • The title above the map is in the same sans-serif as the rest of the widget, not the site's heading font. If it has turned serif, the styles did not paste.
  • Temperatures read like 34.1° vs 23.8° and falls like −17.6. Anything like 34.1Â° means the file was copied through something that changed its encoding — recopy it from a plain-text editor.
  • Narrow the browser window to phone width. The card should move below the map rather than cover it.

4.  Changing the text or updating the figures

Wording

The headline and the standfirst are ordinary HTML near the top of the pasted block. Search for class="ttl" for the headline and class="subt" for the line under it, and edit between the tags. The source line is class="src" and the small print below it is generated by the script — search for hwmeth to change it, or delete that one <p> to drop it.

Figures

The numbers are a snapshot: they do not refresh on their own. To rebuild from the current data, run this in the project and paste the new file in the same way:

python python/make_heatwave_map_html.py

That rewrites both files. Everything visual lives in python/heatwave_map_template.html, so design changes survive a rebuild.

6.  Technical notes for whoever runs the site

  • No network activity. No fetch, no XMLHttpRequest, no external stylesheet, script, font or image. The only URL in the file is the SVG namespace string, which is an identifier and is never requested.
  • No credentials. The data is baked in at build time; no key or endpoint reaches the published file.
  • Pure ASCII. Deliberately, so that copying it between editors cannot corrupt it.
  • Scoped. Every style sits under .hwmap and the script runs inside a closure. It cannot alter the surrounding page, and it carries its own reset so the theme's p and h2 rules cannot alter it.
  • Accessible. Countries are keyboard-reachable and labelled, the card is a labelled dialog, and a hidden data table carries the same figures for screen readers.
  • Light only, and it paints its own white background, so it does not follow a visitor's dark-mode setting into an unreadable state.
